# AI 会话持续保存与 `/resume`（CLI 编号）— 设计说明

**日期**：2026-08-06  
**状态**：已批准（用户选 A：聊天区编号列表 + 数字确认）  
**参考**：Claude Code `/resume` 列表切换 + 边聊边落盘 transcript

## 目标

1. **持续保存**：对话变更后自动写入工作区，关应用可恢复。  
2. **`/resume`**：在聊天区列出编号会话，输入数字确认后恢复完整历史（含代码块校验态）。  
3. **严格正确**：编号与列表快照绑定；恢复后下一轮 API 带完整 messages；元命令不污染会话记忆。

## 存储（Claude 风格本地 transcript）

路径：`.studio/sessions/`

| 文件 | 内容 |
|------|------|
| `index.json` | `active_id`、摘要列表缓存 |
| `{uuid}.json` | 完整会话：messages、profile_id、danger_mode、reply_code_blocks、target_files、title、时间戳 |

写入：先写临时文件再 rename，避免半截 JSON。

## 持续保存触发

- 每次用户/助手消息落定后（含编辑重发、回退确认后）  
- `/danger` `/safe` 切换后  
- `/new` 或切换会话前：先 flush 当前会话  
- 防抖约 300ms，避免连点写盘风暴

## CLI 交互（方案 A）

1. `/resume` 或 `/sessions`  
   - flush 当前会话  
   - 按 `updated_at` 降序编号列出：`1) 标题 · 相对时间 · N条`  
   - 进入 **选号模式**（冻结本次列表快照）  
2. 选号模式下：  
   - `1`…`N` → 加载对应会话，替换 UI 状态，退出选号模式  
   - `/cancel` → 退出选号模式，不改当前会话  
   - 其它输入 → 提示「请输入 1–N 或 /cancel」，**不发往模型**  
3. `/new` → flush 后新建空会话并设为 active  
4. 启动时：加载 `active_id` 会话；无则新建

## 标题规则

取第一条非 `/` 命令的用户消息，截断约 40 字；若无则「新会话」。

## 非目标

- 不做 GUI 弹窗（本版）  
- 不做跨工作区全局会话  
- 不把会话打进模块导出包（仍在 `.studio`）

## 验收

- 对话后杀进程重启 → 仍在最近会话  
- `/resume` 列表编号稳定；输入 `2` 必恢复列表中的第 2 项  
- 恢复后继续提问，上下文含历史  
- `/resume` 交互本身不写入被恢复会话的 messages  
- 单元测试覆盖 save/load/list/编号边界
